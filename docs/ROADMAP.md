# Roadmap

The roadmap prioritizes trustworthy data before advanced AI.

## v0.0.1 — Foundation

**Goal:** Establish the mission, product rules, AEN framework, initial architecture, data model, and Port St. Lucie source catalog.

Deliverables:

- Repository foundation
- Mission, vision, and manifesto
- Core principles
- Product requirements
- AEN framework
- Architecture and data model
- Resident question catalog
- Official-source registry
- Initial schemas

Exit criteria:

- Foundation reviewed and merged
- No unresolved contradiction in the core mission or AEN terminology
- Initial official sources confirmed

## v0.1.0 — Port St. Lucie data discovery

**Goal:** Enumerate and archive the first authoritative financial documents.

Deliverables:

- Latest adopted budget
- Latest budget-in-brief
- Latest available quarterly revenue/expenditure statement
- Latest ACFR
- Prior two adopted budgets
- Millage analyses
- Latest debt and investment reports
- Procurement manual
- Initial capital-project records
- Source manifests with hashes and retrieval dates

Exit criteria:

- Documents are preserved and cataloged
- Extraction feasibility is documented
- Public-record gaps are listed

## v0.2.0 — Financial normalization

**Goal:** Build a canonical representation of one complete fiscal year.

Deliverables:

- Fund crosswalk
- Department and account crosswalks
- Budget-stage model
- Revenue and expenditure tables
- Source lineage
- Reconciliation reports

Exit criteria:

- Core totals reconcile or have documented exceptions
- Budget and actual values are not conflated
- Transfers and restricted funds are handled explicitly

## v0.3.0 — Evidence explorer

**Goal:** Publish a non-AI internal interface for exploring records.

Deliverables:

- Revenue explorer
- Spending explorer
- Source-document viewer
- Fund, department, project, contract, and vendor pages
- Show the Evidence links

Exit criteria:

- A reviewer can reproduce every displayed total
- Data-quality notices are visible

## v0.4.0 — Sourced question answering

**Goal:** Answer the first ten resident questions.

Deliverables:

- Deterministic calculation service
- Retrieval pipeline
- Guarded answer composer
- Claim-level citations
- Answer evaluations and adversarial tests

Exit criteria:

- Ten approved questions pass factuality and citation tests
- Unsupported questions fail safely

## v0.5.0 — Property-tax explainer

**Goal:** Explain the City portion of property taxes without implying false earmarking.

Deliverables:

- Taxing-authority separation
- Millage and taxable-value explanation
- Estimated service allocation methodology
- User-facing disclaimers and evidence

Exit criteria:

- Estimates are reproducible
- City, county, school, and district amounts are not mixed

## v0.6.0 — AEN Review alpha

**Goal:** Produce the first reviewer-approved AEN evidence packet.

Deliverables:

- AEN Review workflow
- Evidence-status vocabulary
- Missing-evidence workflow
- One complete review of a selected Port St. Lucie proposal, program, or project

Exit criteria:

- Findings distinguish fact, calculation, inference, and unresolved questions
- No unsupported allegation or automatic political verdict

## v0.7.0 — Public alpha

**Goal:** Release a limited public Port St. Lucie experience.

Deliverables:

- Accessible public interface
- Search and guided questions
- Data-quality page
- Correction and feedback process
- Privacy and security review

## v1.0 — Port St. Lucie pilot

**Goal:** Demonstrate a repeatable, trustworthy civic-finance product.

Minimum capabilities:

- Multi-year revenue and spending explorer
- Budget-to-actual comparisons
- Property-tax explainer
- Major projects and vendors
- Council authorization links
- Sourced AI answers
- AEN Reviews
- Public data exports
- Correction history

## Expansion after the pilot

1. St. Lucie County
2. Selected Florida cities and counties
3. School districts and special districts
4. State-level modules
5. Jurisdiction onboarding toolkit

Expansion should begin only after the Port St. Lucie model is reproducible and jurisdiction-specific assumptions are separated from the shared platform.
